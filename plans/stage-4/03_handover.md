## 2. Инструкция сопровождения (минимум для приёмника)

**Правка контента:** файл `docs/modules/<код>/…` → commit → push: GitHub Actions сам валидирует (`validate_content.py`), собирает strict и публикует. Ошибка валидации = публикация не происходит (защита от сломанных квизов).

**Регламентные операции:**
- новая навигация после добавления файлов: `python tools/gen_nav.py`;
- перегенерация PDF-конспектов: `node tools/make_module_pdfs.mjs … && python tools/merge_pdfs.py docs/pdf`;
- проверка кодов результатов: `python tools/registry_check.py codes.txt`;
- смена соли сертификатов при передаче: одна строка в 3 файлах (см. `plans/stage-3/04_deployment.md`).

**Что нельзя делать:** класть в публичный репозиторий реальные координаты водоёмов, персональные данные слушателей, тендерные документы; менять quiz-JSON без прогона валидатора.

## 3. Приёмо-передаточные шаги

1. Transfer репозитория GitHub в организацию получателя (Pages переезжает автоматически, URL меняется — обновить `site_url`).
2. Передача офлайн-носителя (уровень C + origin) по акту.
3. ToT-инструктаж сопровождающего (0,5 дня): цикл правки → валидация → публикация.
4. Подписание акта передачи (перечень объектов — таблица раздела 1).
