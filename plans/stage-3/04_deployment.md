# Публикация платформы

> **Актуальная схема (2026-07-02):** хостинг — **Firebase Hosting** (https://folur-kaz-platform.web.app/, проект `folur-kaz-platform`), исходники — **приватный** GitHub-репозиторий vel5id/folur-platform. Деплой: `tools/deploy_firebase.sh`; синхронизация репо: `tools/publish_platform.sh`; CI на push — валидация + strict-сборка. Раздел ниже (GitHub Pages) сохранён как альтернатива для вузов-приёмников с публичным репозиторием.

## Архив: вариант GitHub Pages

> Роль-владелец: IT-разработчик · Предусловие пилота: платформа доступна слушателям по публичному URL.

## 1. Шаги публикации

1. Создать GitHub-репозиторий (организация КРУ или проектная), запушить содержимое `/home/h621l/undp-fable-5` (raw-данные и артефакты уже в `.gitignore`).
2. В настройках репозитория: Pages → Source: GitHub Actions.
3. Workflow уже в репозитории: `.github/workflows/deploy.yml` (сборка mkdocs + публикация). PDF-конспекты генерируются локально (`tools/make_module_pdfs.mjs`) и добавляются через Git LFS **или** прикладываются к GitHub Releases — решение за владельцем репо (45 МБ).
4. После первого деплоя заменить `site_url` в `mkdocs.yml` на реальный URL и обновить Colab-плейсхолдеры ноутбуков.
5. Прогнать смоук: главная, любой модуль, аттестация (pre и final), verify-страница, скачивание PDF.

## 2. Что остаётся локальным/внутренним

- `data-not-anonymys/` (уровень C) — никогда не пушится (в `.gitignore`);
- `project/zenodo-package/` — публикуется на Zenodo, не на GitHub Pages, после юридического чек-листа;
- KPI-реестр — Google Sheets проекта, не в репозитории (персональные данные слушателей).

## 3. Смена соли сертификатов (рекомендация перед боевым запуском)

`CERT_SALT` в `quiz-engine.js`/`verify.js`/`registry_check.py` — заменить на проектную строку одним коммитом (3 файла синхронно). Это не делает коды криптостойкими, но исключает генерацию «валидных» кодов по опубликованному исходнику без чтения соли из репо. Полноценное решение — Open Badges на Этапе 4.
