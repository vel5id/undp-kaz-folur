# Методика KPI-учёта и реестр слушателей (KPI 2.12 ПРООН)

> Роль-владелец: координатор обучения · Принцип: **два независимых следа** — подписанный бумажный лист + цифровой код результата.

## 1. Структура реестра (Google Sheets / Excel)

Лист «Слушатели»:

| Колонка | Источник |
|---|---|
| ID слушателя (выдаётся при регистрации, он же — идентификатор в тест-движке) | координатор |
| ФИО, организация/хозяйство, район | подписанный лист |
| Категория: МСБ / агроном / госслужащий / студент (для KPI считаются МСБ-категории) | подписанный лист |
| Поток №, модули | координатор |
| Pre-тест: %, счёт, дата | код результата (`registry_check.py`) |
| Post-тест: %, счёт, дата | код результата |
| Сертификат: да/нет | код сертификата |
| Прикладной продукт (проект на своей земле): принят/нет | тренер |
| Анкета обратной связи: сдана | координатор |

Лист «Свод»: счётчики по потокам и категориям, прогресс к 360, контрольные точки (нед. 19/25/31).

## 2. Процесс обработки кодов

1. Слушатель после pre- и post-теста копирует «код результата» (кнопка на странице аттестации) и отправляет координатору (мессенджер/форма) либо показывает QR.
2. Координатор собирает коды в текстовый файл (по одному в строке) и запускает:
   `python3 project/platform/tools/registry_check.py codes.txt > rows.csv`
3. Валидные строки (`OK;…`) вставляются в реестр; строки `ИСПОРЧЕН` возвращаются слушателю на пересдачу кода.
4. Прирост компетенций: колонка `post% − pre%` по слушателю; свод по потоку — в отчёт этапа.

## 3. Гарантии достоверности

- индивидуальные варианты (сид: ID слушателя + режим) — списывание у соседа не работает;
- контрольная сумма кода — подделка «на глаз» и опечатки отсеиваются; окончательная сверка — подписанные листы;
- pre и post — разные варианты одного банка (сопоставимая сложность, эффект запоминания варианта исключён);
- ограничение честно фиксируется в отчётах: коды не криптоподпись; юридический след — бумажные листы регистрации.

## 4. Отчётность

Ежепоточный мини-свод (обучено, средний прирост, доля сертификатов) + сводный отчёт на контрольных точках. В отчёты ПРООН попадают только числа из реестра; формулировка «обучено ≥360» до факта не используется.
