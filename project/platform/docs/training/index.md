# Для тренера и координатора

Рабочие материалы пилотного обучения (Этап 3). Программа потоков и KPI-методика — во внутренних документах проекта (`plans/stage-3/`).

## Структура тренинг-дня (формат 8 ак. часов)

| Блок | Время | Содержание |
|---|---|---|
| Открытие | 30 мин | регистрация (подписной лист!), выдача ID слушателя, вход на платформу |
| Pre-тест | 30 мин | страница аттестации модуля с `?mode=pre`; слушатель отправляет координатору «код результата» |
| Лекционный блок | 2×60 мин | по лекциям модуля; региональный кейс разбирается обязательно |
| Практикум | 2×60 мин | guided-проект модуля; тренер идёт по шагам практикума |
| ИИ-блок | 45 мин | задание из «ИИ-ассистент в работе» своего уровня; завершить шагом верификации |
| «Проект на своей земле» | 45 мин | постановка домашнего задания на данных хозяйства слушателя |
| Итоги дня | 15 мин | вопросы, план следующего занятия |

Post-тест и сертификат — на финальном занятии модуля (обычный режим страницы аттестации; при ≥75% слушатель формирует сертификат сам, код результата — координатору).

## Чек-лист тренера до занятия

- [ ] Интернет и проектор в аудитории; резерв — офлайн-пакет и PDF-конспекты
- [ ] У слушателей: браузер; для Colab-практикумов — Google-аккаунты (резервные учётки группы наготове)
- [ ] Для GEE-практикумов: аккаунты Earth Engine зарегистрированы заранее (одобрение занимает время)
- [ ] Для QGIS-практикумов: QGIS LTR установлен / установщики на флешке
- [ ] ИИ-сервисы блока доступны из аудитории; если нет — скриншот-сценарий (задания выполнимы без ИИ)
- [ ] Датасеты модуля скачиваются (уровень A — `datasets/`; внешние — ссылки из лекций)
- [ ] Подписные листы распечатаны; ID слушателей выданы

## Правила честного результата

1. Каждый слушатель работает под **своим ID** — от него зависит индивидуальный вариант теста.
2. Pre-тест — до начала обучения, без подготовки; это точка отсчёта прироста, а не экзамен.
3. Коды результатов собираются в день сдачи (файл «по коду в строке» → координатору).
4. Прикладной продукт слушателя проверяется по критериям из `assessment/` модуля — без него модуль не считается завершённым.

## Анкета обратной связи (после каждого модуля)

Формат — бумажный или форма; вопросы:

1. Что из модуля вы примените в хозяйстве в ближайший месяц? (открытый)
2. Какой раздел был самым полезным / самым трудным? (открытый)
3. Темп и объём: слишком быстро / нормально / слишком медленно
4. Практикум: смог(ла) выполнить сам(а) / с помощью / не смог(ла)
5. ИИ-задание: буду использовать инструмент дальше — да / нет / не уверен(а)
6. Оценка модуля 1–5 и что улучшить (открытый)

Сводку по анкетам координатор передаёт методологу после каждого потока — правки модулей вносятся в репозиторий (журнал доработки).
