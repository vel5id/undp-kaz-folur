# ИИ-ассистент в работе: первый скрипт с ИИ-напарником

> Модуль **П4: Python и Jupyter для специалистов** · Уровень ИИ-слоя: **Low-code** · ~45 мин
> Инструменты: Google Colab + LLM-ассистент (встроенный помощник Colab или любой чат-ассистент — Claude и аналоги; каждый инструмент заменяем открытым аналогом).

!!! warning "Главное правило: ИИ ускоряет — человек верифицирует"
    Результат ИИ без независимой проверки — не результат. Всё задание ниже выполнимо и полностью без ИИ (код дан в [практикуме](practicum/01-pervyj-rabochij-skript.md)) — ИИ-слой ускоряет работу, но не является условием прохождения модуля.

## Цель задания

Освоить рабочий цикл специалиста уровня low-code: **сформулировать задачу по-русски → получить код от LLM-ассистента → исполнить в Colab → верифицировать результат по контрольным точкам**. После задания вы сможете поручать ИИ рутинное написание кода под ваши таблицы, оставляя себе постановку задачи и контроль качества — ровно то распределение ролей, которое принято в реальных командах анализа данных.

## Почему постановка задачи важнее кода

LLM-ассистент пишет типовой pandas-код быстро и в основном корректно, но он не знает ваших данных: имён колонок, физического диапазона значений, того, что нули в промерах бывают законными. Всё это обязан сообщить постановщик — вы. Рабочий промпт-паттерн из четырёх частей:

1. **Роль и контекст** — «Я работаю в Google Colab, у меня CSV с эхолотными промерами»;
2. **Данные** — точные имена колонок, размер, особенности: «колонки `point_id, x_m, y_m, depth_m`, 80 000 строк, глубины 0–16,1 м, нулевые значения — частично законные точки берега, их удалять нельзя»;
3. **Шаги** — что именно сделать, по пунктам (чистка по диапазону → показатели → гистограмма → сохранение нового CSV);
4. **Формат ответа** — «одна ячейка кода с комментариями по-русски; исходный файл не перезаписывать».

Чем конкретнее пункты 2–3, тем меньше правок. Расплывчатый промпт «почисти мне данные» даёт код, который молча удалит ваши нули.

## Пошаговое задание

**Шаг 1. Подготовка (5 мин).** Откройте новый Colab-ноутбук, загрузите `bathymetry-training-80k.csv` (см. [Датасеты](../../datasets.md)). В текстовой ячейке зафиксируйте цель: «Паспорт водоёма: чистка, показатели, гистограмма — код пишет ИИ-ассистент, верификация моя».

**Шаг 2. Постановка задачи (10 мин).** Составьте промпт по паттерну выше и запросите у ассистента код, который: (а) читает CSV; (б) печатает протокол чистки — число строк до/после фильтра физического диапазона 0–17 м и число дубликатов; (в) считает среднюю, медианную и максимальную глубину и долю точек мельче 2 м; (г) строит гистограмму глубин с подписанными осями; (д) сохраняет очищенную версию в **новый** файл. Сохраните текст промпта в текстовой ячейке ноутбука — промпт является частью протокола работы.

**Шаг 3. Ревью перед запуском (5 мин).** Прочитайте предложенный код **до** исполнения и проверьте три пункта: читается ли правильный файл; не перезаписывается ли исходник (`to_csv` только в новое имя!); не удаляются ли нулевые глубины. Нашли проблему — не правьте вручную, а сообщите ассистенту: «нули удалять нельзя, исправь» — умение добиваться правки итерациями и есть навык.

**Шаг 4. Исполнение (5 мин).** Запустите код. Ошибка? Скопируйте traceback целиком ассистенту и попросите исправить ([лекция 1](lectures/01-zapuskaem-python-v-colab.md), §4.2). Две-три итерации — норма.

**Шаг 5. Обязательная верификация (15 мин).** Проверьте результат ИИ независимо — по контрольным точкам, которые вы знаете о данных заранее:

| Контрольная точка | Ожидание | Как проверить |
|---|---|---|
| Число исходных строк | ровно 80 000 | `len(pd.read_csv(RAW))` — своя ячейка, не код ИИ |
| Диапазон глубин чистой версии | 0…16,1 м | `clean["depth_m"].min()`, `.max()` |
| Баланс строк | удалено + осталось = исходные | арифметика по протоколу |
| Нулевые отсчёты | сохранены, доля ≈4–5 % | `(clean["depth_m"] == 0).mean()` |
| Средняя и медиана | ≈3,4 м и ≈3,0 м — сходится с `df.describe()` | сверка с шагом 2 [практикума](practicum/01-pervyj-rabochij-skript.md) |
| Воспроизводимость | полный прогон без ошибок | Restart & Run all |

Любое расхождение — возврат к шагу 3: разбираетесь, чей это дефект (постановки или кода), и добиваетесь исправления. В текстовой ячейке зафиксируйте итог верификации: какие точки сошлись, сколько итераций потребовалось.

**Шаг 6 (по желанию). Свои данные.** Повторите цикл для собственного CSV из шага 7 практикума — теперь контрольные точки формулируете вы сами, до обращения к ИИ. Это главный перенос навыка: верификация начинается со знания собственных данных.

## Критерии зачёта

- [ ] В ноутбуке сохранён текст промпта (постановка задачи по 4-частному паттерну);
- [ ] Код получен от ассистента и исполнен; итерации правок видны или описаны;
- [ ] Ревью до запуска выполнено: исходный файл не перезаписан, нули не удалены;
- [ ] Таблица верификации заполнена: все шесть контрольных точек проверены **отдельными ячейками, написанными вами**, расхождения объяснены;
- [ ] Ноутбук проходит Restart & Run all;
- [ ] Вывод в финальной текстовой ячейке: что ИИ сделал хорошо, где ошибся, что вы изменили бы в промпте.

Незачёт при любом из двух: верификация выполнена кодом самого ассистента «проверь сам себя» (это не независимая проверка) или результат принят на веру без таблицы контрольных точек.
