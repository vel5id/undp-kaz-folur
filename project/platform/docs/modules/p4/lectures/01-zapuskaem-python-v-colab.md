<p>Масштаб. Таблица с журналом взвешиваний на тысячу строк листается глазами. Файл эхолотной съёмки на 80 000 строк — уже нет: Excel его откроет, но каждая ручная операция (найти подозрительные значения, пересчитать колонку) превращается в многоминутное ожидание и риск случайно испортить данные. <p>Воспроизводимость. Отчёт, собранный ручными операциями «скопировал — вставил — отсортировал — удалил строки», невозможно повторить точно. <p>Автоматизация. Если операция повторяется — каждую неделю приходит новая выгрузка, каждый сезон новый журнал, — ручная обработка съедает часы. Скрипт, написанный один раз, обрабатывает и один файл, и сто файлов одинаково: меняется только имя файла. К пакетной обработке мы придём в лекции 3.</p>

Правило профессионала: перед тем как считать результат готовым — Restart &amp; Run all (перезапустить ядро и исполнить всё сверху вниз). glubina = 3.4            # число с дробной частью (float)

<p>Продолжая предыдущий материал, переходим к вопросу «3.2 Списки и словари», который связывает изложенное выше с тем, что рассматривается далее.</p>

```python
glubiny = [0.27, 2.87, 3.4, 16.1, 0.0]   # список — упорядоченный набор
print(len(glubiny))      # 5 — длина
print(max(glubiny))      # 16.1
print(glubiny[0])        # 0.27 — нумерация с нуля!

zapis = {"point_id": 1, "x_m": 34202.2, "y_m": 37336.1, "depth_m": 0.27}
```

<p>Список (<code>list</code>) хранит значения по порядку, словарь (<code>dict</code>) — пары «ключ → значение», как строка таблицы с именованными колонками. <p>Продолжая предыдущий материал, переходим к вопросу «3.3 Условия и циклы», который связывает изложенное выше с тем, что рассматривается далее.</p>

```python
melkovodie = 0
for d in glubiny:            # цикл: перебираем значения по одному
    if d < 2.0:              # условие
        melkovodie = melkovodie + 1

dolya = melkovodie / len(glubiny)
print(f"Доля точек мельче 2 м: {dolya:.0%}")
```

<p>Цикл <code>for</code> повторяет блок для каждого элемента; условие <code>if</code> исполняет блок только когда выражение истинно. Обратите внимание на отступы: в Python вложенность блоков обозначается сдвигом на четыре пробела, и неровный отступ — синтаксическая ошибка, а не оформление. Редактор расставляет отступы автоматически, но при копировании кода из мессенджеров они часто ломаются — это первое, что стоит проверить.</p>

<p>Продолжая предыдущий материал, переходим к вопросу «3.4 Функции и импорт», который связывает изложенное выше с тем, что рассматривается далее.</p>

```python
def dolya_melkovodiy(spisok, porog=2.0):
    """Доля значений мельче порога (по умолчанию 2 м)."""
    melkih = 0
    for d in spisok:
        if d < porog:
            melkih += 1
    return melkih / len(spisok)

print(dolya_melkovodiy(glubiny))        # порог 2 м
print(dolya_melkovodiy(glubiny, 5.0))   # порог 5 м

import statistics                        # модуль стандартной библиотеки
print(statistics.median(glubiny))
```

<p>Функция упаковывает расчёт в переиспользуемый блок с именем: написали один раз — вызываете сколько угодно, меняя аргументы. Именно так растут ваши личные инструменты: сегодня функция «доля мелководий», завтра — «паспорт водоёма». <code>import</code> подключает готовые модули: <code>statistics</code>, <code>csv</code>, <code>math</code> входят в стандартную библиотеку, а мощные внешние библиотеки (pandas, matplotlib) подключаются так же — с ними мы работаем со следующей лекции.</p>

<p>Разберите строку <code>def dolya_melkovodiy(spisok, porog=2.0):</code> по частям: <code>def</code> объявляет функцию, в скобках — аргументы, а <code>porog=2.0</code> — аргумент со значением по умолчанию: его можно не указывать при вызове. Строка в тройных кавычках сразу под заголовком — докстринг, короткое описание назначения; команда <code>help(dolya_melkovodiy)</code> покажет его любому пользователю вашей функции, включая вас через полгода. <code>return</code> отдаёт результат наружу — без него функция посчитает и промолчит: типичная ошибка новичка, когда «функция вроде работает, а результата нет».</p>

<p>Продолжая предыдущий материал, переходим к вопросу «4.1 Читаем настоящий CSV», который связывает изложенное выше с тем, что рассматривается далее.</p>

<p>CSV (comma-separated values) — текстовый формат таблиц: первая строка — имена колонок, дальше — данные через запятую. Именно в CSV распространяется учебный датасет платформы. Прочитать его можно даже без pandas — стандартным модулем <code>csv</code>:</p>

```python
import csv

n = 0
maks = 0.0
with open("bathymetry-training-80k.csv") as f:
    for row in csv.DictReader(f):        # каждая строка -> словарь
        d = float(row["depth_m"])        # текст -> число
        n += 1
        if d > maks:
            maks = d

print(f"Записей: {n}, максимальная глубина: {maks} м")
```

<p>Здесь видно всё изученное сразу: файл открывается конструкцией <code>with open(...)</code> (она гарантирует закрытие файла), цикл перебирает строки-словари, <code>float()</code> превращает текст <code>&quot;16.1&quot;</code> в число. На 80 000 строк этот код отрабатывает за секунды — то, что в Excel потребовало бы осторожной ручной работы. В лекции 2 pandas сожмёт этот фрагмент до одной строки, но понимать, что происходит «под капотом», вы теперь будете всегда.</p>

<p>Код падает у всех, включая профессионалов; разница в реакции. Python при ошибке печатает traceback — трассировку: цепочку вызовов и в последней строке — тип и описание ошибки. Читать traceback нужно снизу вверх: последняя строка говорит «что случилось», строки выше — «где».</p>

<p>Вывод: traceback читается снизу вверх — последняя строка говорит «что», строки выше — «где»; типовые ошибки новичка лечатся за пять минут.</p>

<p>Алгоритм действий: прочитать последнюю строку → найти в traceback номер строки своего кода → проверить очевидное (опечатки, порядок исполнения ячеек, загружен ли файл). Если за пять минут причина не нашлась — скопируйте traceback целиком в поиск или ИИ-ассистенту: разбор чужих ошибок отлажен десятилетиями, ваша почти наверняка типовая. ## Тема П4.1. Региональный кейс

<p>Ситуация: Агроном хозяйства в Акмолинской области хочет сравнить влагообеспеченность двух последних вегетационных сезонов: сложить суточные осадки за май–август каждого года. Метеопоста в хозяйстве нет, но открытый сервис NASA POWER (power.larc.nasa.gov) бесплатно выдаёт суточные агроклиматические ряды (осадки, температура) для любой точки по координатам — достаточно указать точку своего района в веб-форме и скачать CSV. Excel для одной пары сезонов справился бы, но агроном хочет решение, которое следующей весной отработает за минуту.</p>

<p>Данные: NASA POWER Data Access Viewer — суточные ряды параметра «осадки» (PRECTOTCORR) для точки в своём районе, экспорт в CSV; учебный датасет платформы для тренировки чтения CSV.</p>

<p>Задача:</p>

<p>Скачать CSV c суточными осадками за два сезона и загрузить его через «Свои файлы» в редактор.</p>

<p>Циклом по строкам просуммировать осадки за май–август каждого года (по колонкам года и месяца в файле NASA POWER).</p>

<p>Оформить расчёт функцией <code>summa_osadkov(fajl, god)</code> и вывести результат f-строкой для обоих лет.</p>

<p>Разбор: Ход решения повторяет §4.1: <code>csv.DictReader</code>, преобразование <code>float()</code>, условие на месяц <code>if 5 &lt;= mesyac &lt;= 8</code>, накопление суммы в переменной. Конкретные миллиметры зависят от выбранной точки и лет — их вычисляете вы, а не лекция; проверка правдоподобия — по известной климатологии региона: Северный Казахстан — зона недостаточного увлажнения, сезонные суммы измеряются десятками–сотнями миллиметров, и результат в тысячи миллиметров означает ошибку в коде (например, суммирование всех месяцев или дублирование строк). Такая проверка «числа на здравый смысл» — первый навык верификации, который в ИИ-задании станет обязательным шагом.</p>
