# ИИ-ассистент в работе: ряд NDVI по вашему полю с ИИ-напарником

> Модуль **П7: ДЗЗ и БПЛА для мониторинга земель** · Уровень ИИ-слоя: **Low-code** · ~45 мин
> Инструменты: Google Colab + LLM-ассистент (встроенный помощник Colab или любой чат-ассистент — Claude и аналоги; каждый инструмент заменяем открытым аналогом).

!!! warning "Главное правило: ИИ ускоряет — человек верифицирует"
    Результат ИИ без независимой проверки — не результат. Всё задание ниже выполнимо и полностью без ИИ (код дан в [практикуме](practicum/01-ryad-ndvi-i-razbor-oblyota.md)) — ИИ-слой ускоряет работу, но не является условием прохождения модуля.

## Цель задания

Освоить рабочий цикл специалиста уровня low-code на задаче мониторинга: **сформулировать задачу по-русски → получить код расчёта ряда NDVI от LLM-ассистента → исполнить в Colab → верифицировать результат по контрольным точкам и по собственным полевым наблюдениям**. После задания вы сможете поручать ИИ рутинное написание кода обработки снимков, оставляя себе постановку задачи, агрономическую интерпретацию и контроль качества — ровно то распределение ролей, которое принято в реальных командах агромониторинга.

## Почему постановка задачи важнее кода

LLM-ассистент пишет типовой код расчёта NDVI и сборки ряда быстро, но он не знает **вашего поля и ваших снимков**: какие даты облачные, где границы поля, какая фенофаза, что нули и отрицательные значения бывают законными (вода, тень). Всё это обязан сообщить постановщик — вы. Рабочий промпт-паттерн из четырёх частей (тот же, что в [П4, ИИ-задание](../p4/ai-assistant.md)):

1. **Роль и контекст** — «Я работаю в Google Colab, у меня выгрузки Sentinel-2 L2A по одному полю за 5 сезонов»;
2. **Данные** — точные имена файлов и каналов: «на каждый сезон каналы B04 (красный) и B08 (NIR) и слой SCL; каналы — целые числа, привести к float32; коды облаков/теней в SCL — по документации, исключить их из расчёта»;
3. **Шаги** — по пунктам: расчёт NDVI с защитой от деления на ноль → маска облаков по SCL → среднее по полю и доля чистых пикселей → сборка таблицы «сезон → NDVI → доля чистых» → график;
4. **Формат ответа** — «одна функция + цикл по сезонам; исходные файлы не изменять; NDVI проверить на диапазон −1…+1».

Чем конкретнее пункты 2–3, тем меньше правок. Расплывчатый промпт «посчитай мне NDVI по снимкам» даёт код без маски облаков — и ряд с ложными провалами.

## Пошаговое задание

**Шаг 1. Подготовка (5 мин).** Откройте Colab, загрузите выгрузки B04/B08/SCL за несколько сезонов (из [практикума](practicum/01-ryad-ndvi-i-razbor-oblyota.md), шаг 1–2). В текстовой ячейке зафиксируйте цель: «Ряд NDVI по полю за 5 сезонов с маской облаков — код пишет ИИ-ассистент, верификация моя, включая сверку с полем».

**Шаг 2. Постановка задачи (10 мин).** Составьте промпт по паттерну выше и запросите код, который: (а) считает NDVI из B04/B08 с приведением к float32 и защитой `+1e-9`; (б) маскирует облака/тени по SCL; (в) возвращает средний NDVI по полю и долю чистых пикселей на каждый сезон; (г) собирает таблицу и строит график динамики. Сохраните текст промпта в текстовой ячейке — промпт является частью протокола работы.

**Шаг 3. Ревью перед запуском (5 мин).** Прочитайте код **до** исполнения и проверьте: приведены ли каналы к float32 ([лекция 1, §3.2](lectures/01-chitaem-pole-iz-kosmosa-ndvi.md)); есть ли защита от деления на ноль; **применяется ли маска облаков SCL** (без неё ряд врёт — [лекция 2, §2](lectures/02-mnogoletnij-ryad-ndvi-problemnye-zony.md)); не перезаписываются ли исходные файлы. Нашли проблему — не правьте вручную, а сообщите ассистенту: «маску облаков ты не применил, добавь SCL» — умение добиваться правки итерациями и есть навык.

**Шаг 4. Исполнение (5 мин).** Запустите код. Ошибка? Скопируйте traceback целиком ассистенту и попросите исправить ([П4, лекция 1, §4.2](../p4/lectures/01-zapuskaem-python-v-colab.md)). Две-три итерации — норма.

**Шаг 5. Обязательная верификация (15 мин).** Проверьте результат ИИ независимо — по контрольным точкам, которые вы знаете заранее:

| Контрольная точка | Ожидание | Как проверить |
|---|---|---|
| Диапазон NDVI | все значения в −1…+1 | `np.nanmin`, `np.nanmax` — своя ячейка, не код ИИ |
| Маска облаков применена | облачные даты не дают ложных провалов | сверка формы кривой с осмотром сцен в Copernicus Browser |
| Доля чистых пикселей | у оставленных дат — выше разумного порога | колонка `dolya_chistyh` в таблице ([лекция 2, §2.3](lectures/02-mnogoletnij-ryad-ndvi-problemnye-zony.md)) |
| Сезонная логика | NDVI на колошении выше, чем на голой почве | сравнение с фенопрофилем ([лекция 2, §1.1](lectures/02-mnogoletnij-ryad-ndvi-problemnye-zony.md)) |
| Визуальная сверка | тёмные зоны карты совпадают с реальными | наложение на цветной снимок в браузере ([лекция 1, §3.3](lectures/01-chitaem-pole-iz-kosmosa-ndvi.md)) |
| **Сверка с полем** | устойчиво низкая зона совпадает с известным вам проблемным участком | ваши полевые наблюдения — главная верификация |
| Воспроизводимость | полный прогон без ошибок | Restart & Run all |

Любое расхождение — возврат к шагу 3: разбираетесь, чей это дефект (постановки или кода), и добиваетесь исправления. Зафиксируйте итог верификации в текстовой ячейке.

**Шаг 6 (по желанию). Своё поле.** Повторите цикл для собственного поля из рамки «Проект на ВАШЕЙ земле» ([практикум](practicum/01-ryad-ndvi-i-razbor-oblyota.md)) — теперь контрольные точки, включая ожидаемое расположение проблемной зоны, формулируете вы сами до обращения к ИИ. Это главный перенос навыка: верификация начинается со знания собственного поля.

## Обязательный шаг верификации результата ИИ

Инвариант ИИ-слоя платформы: **каждое ИИ-задание завершается независимой проверкой**. Для П7 она двухуровневая и обе части обязательны:

1. **Техническая** — диапазон −1…+1, применённая маска облаков, доля чистых пикселей, воспроизводимость (таблица выше). Проверяется **отдельными ячейками, написанными вами**, а не кодом самого ассистента.
2. **Агрономическая (специфика П7)** — сверка спутникового вывода с реальностью: форма кривой против фенопрофиля, тёмные зоны против цветного снимка и, главное, устойчиво проблемная зона против того, что вы знаете о поле сами (где урожай ниже, где стоит вода, где солончак). ИИ не был на вашем поле — эту проверку может сделать только человек.

Результат, не прошедший обе проверки, к сдаче не принимается.

## Критерии зачёта

- [ ] В ноутбуке сохранён текст промпта (постановка по 4-частному паттерну);
- [ ] Код получен от ассистента и исполнен; итерации правок видны или описаны;
- [ ] Ревью до запуска выполнено: float32, защита от деления на ноль, **маска облаков SCL применена**, исходные файлы не перезаписаны;
- [ ] Таблица технической верификации заполнена **своими ячейками**; все значения NDVI в −1…+1; облачные даты отсеяны по доле чистых пикселей;
- [ ] Выполнена агрономическая сверка: форма кривой, наложение на цветной снимок и сопоставление проблемной зоны с собственными наблюдениями о поле;
- [ ] Ноутбук проходит Restart & Run all;
- [ ] Вывод в финальной текстовой ячейке: что ИИ сделал хорошо, где ошибся (например, забыл маску облаков), что вы изменили бы в промпте.

Незачёт при любом из двух: верификация выполнена кодом самого ассистента «проверь сам себя» (это не независимая проверка) или вывод о проблемной зоне принят без агрономической сверки с полем.
