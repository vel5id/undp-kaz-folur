## Сценарный кейс (экспертная проверка)

> Образец сценарной части экзамена. Тест-движок платформы генерирует индивидуальные варианты с другими параметрами; проверка — экспертная, по критериям ниже.

**Ситуация.** Кооператив из четырёх хозяйств в Костанайской области (совокупно — крупный массив пашни под пшеницей, поля по 200–400 га) получил предложение подрядчика: «ежемесячная сплошная БПЛА-съёмка всех полей с GSD 2 см, мультиспектр, передача карт NDVI в PDF». Правление просит вашего заключения как специалиста по данным. Дополнительно известно: у кооператива нет ни одного оцифрованного слоя границ полей; журналы ведутся в Excel без координат; прошлогодний спор с соседним хозяйством о потраве показал, что архивных снимков никто найти не смог.

**Задание (ответ — 1–1,5 страницы):**

1. Оцените предложение подрядчика по решётке «разрешение–периодичность–покрытие» (Урок 3): какие элементы избыточны для заявленных задач мониторинга зерновых, какие условия передачи данных отсутствуют?
2. Предложите альтернативную архитектуру системы данных кооператива по методике пяти шагов (Урок 1, раздел 5): минимальный стартовый контур из открытых данных, место БПЛА в ней, приоритетные «дыры» жизненного цикла (границы, журналы, архив).
3. Сформулируйте требования к любому будущему договору на съёмку: форматы, метаданные, геопривязка, права на данные (Уроки 2 и 4).
4. Укажите, какие утверждения в вашем заключении опираются на проверяемые расчёты/источники, а какие являются экспертной оценкой — явно разделите их.

**Критерии оценивания (по 25%):** корректное применение решётки выбора платформы с числовой аргументацией (GSD против размера объектов мониторинга); архитектура цикла с приоритизацией стадий; полнота договорных требований к данным (формат + метаданные + СК + права + логи); дисциплина честности — разделение проверяемого и оценочного. Зачёт кейса — от 75% суммарно.
