# Практикум: карта землепользования района СКО

> ⏱ **Трудозатраты:** 60–90 мин практики (guided-проект).
>
> Модуль **[А2: Геоинформатика и пространственный анализ](../index.md)**.
> Инструменты: QGIS (свободный, кроссплатформенный); опционально — Google Colab (проверка расчёта).
> Данные: ESA WorldCover 10 м, OpenStreetMap, Sentinel-2 L2A (Copernicus), учебный ортофотоплан из набора платформы — всё открыто и бесплатно.

## Цель практикума

**[Bloom: применять]** Самостоятельно собрать в QGIS корректный ГИС-проект района Северо-Казахстанской области и довести его до прикладного продукта модуля: **карты землепользования с зональной статистикой классов и паспортом качества**, с подложкой ортофотоплана БПЛА на верификационном участке.

Практикум объединяет все четыре лекции модуля: [проекции и топологию](../lectures/01-vector-raster-projections.md), [инструменты и открытые данные](../lectures/02-qgis-python-stack.md), [зональную статистику](../lectures/03-spatial-analysis.md), [совмещение масштабов и верификацию](../lectures/04-ai-uav-integration.md).

## Что нужно подготовить

- [ ] **QGIS** (актуальная LTR-версия с сайта qgis.org) с плагинами **QuickOSM** и **QuickMapServices** (Модули → Управление модулями).
- [ ] **ESA WorldCover** — тайл на территорию района: скачивается с <https://esa-worldcover.org/> (открыто, CC BY) или берётся из учебного набора платформы.
- [ ] **Учебный ортофотоплан** участка (готовый набор платформы — дрон не обязателен): `<URL будет назначен при создании репозитория ноутбуков>`.
- [ ] Опционально: сцена **Sentinel-2 L2A** свежей даты с [Copernicus Data Space](https://dataspace.copernicus.eu/) (бесплатная регистрация) — для актуального визуального фона.
- [ ] 60–90 минут времени; результаты сохраняйте после каждого шага.

Рабочий район по умолчанию — **Кызылжарский район СКО**; допускается любой другой район СКО / Костанайской / Акмолинской области (см. рамку «Проект на ВАШЕЙ земле»).

## Задание

### Шаг 1: каркас проекта и СК (10 мин)

1. Создайте папку проекта `landuse-sko/` и новый проект QGIS `landuse.qgz` в ней.
2. Установите СК проекта: **EPSG:32642 (WGS 84 / UTM zone 42N)** — Проект → Свойства → Система координат. (Для района Костанайской области западнее 66° в.д. — EPSG:32641; проверьте долготу своего района.)
3. Подключите веб-подложку OSM через QuickMapServices — визуальный контекст для контроля следующих шагов.

**Ожидаемый результат:** пустой проект с правильной СК и подложкой; в правом нижнем углу QGIS — `EPSG:32642`.

### Шаг 2: граница района из OSM (10 мин)

1. QuickOSM → Быстрый запрос: ключ `boundary`, значение `administrative`, территория — название района (или скачайте границу из учебного набора).
2. Из результата выберите полигон района: проверьте `admin_level` и название в атрибутах (§3.1 лекции 2 — иерархия границ OSM; уровень района отличается от области и сельского округа).
3. Сохраните выбранный объект в GeoPackage проекта: ПКМ по слою → Экспорт → Сохранить объекты как… → формат GeoPackage, файл `landuse.gpkg`, слой `boundary_raion`, **СК EPSG:32642** (физическое перепроецирование — §2.4 лекции 1).
4. Проверьте геометрию: Вектор → Проверка геометрии; при ошибках — «Исправить геометрии» и повторная проверка.

**Ожидаемый результат:** валидный полигон района в `landuse.gpkg`, в метрической СК. Контроль: инструмент измерения площади даёт величину того же порядка, что справочная площадь района (тысячи км²).

### Шаг 3: слой землепользования WorldCover (15 мин)

1. Добавьте скачанный тайл WorldCover (GeoTIFF) в проект. Проверьте в свойствах слоя: СК источника (WorldCover распространяется в EPSG:4326), значение NoData, тип пикселя (байт — категориальные классы).
2. Обрежьте растр по границе района: Растр → Извлечение → Обрезать растр по маске; маска — `boundary_raion`; **целевая СК — EPSG:32642**; передискретизация — **ближайший сосед** (категориальный растр! — §3.3 лекции 1).
3. Сохраните результат как `worldcover_raion.tif` в папку проекта и постройте пирамиды (Свойства слоя → Пирамиды).
4. Настройте символику «Палетка/уникальные значения» по классам WorldCover и подпишите классы согласно официальной легенде продукта (вода, древесная растительность, травянистые, пашня, застройка и т. д.).

**Ожидаемый результат:** растр классов, обрезанный по району, в СК проекта, с читаемой легендой.

### Шаг 4: зональная статистика классов (15 мин)

1. Панель обработки → «Отчёт об уникальных значениях растрового слоя» (или «Зональная гистограмма» по слою границы) — получите число пикселей каждого класса в границах района.
2. Пересчитайте пиксели в гектары: один пиксель 10×10 м = 0,01 га. Удобно сделать это в полевом калькуляторе таблицы результата или в электронной таблице.
3. Посчитайте долю каждого класса в процентах от площади района. **Контроль баланса площадей** (§2 лекции 3): сумма площадей классов должна совпадать с площадью полигона района с точностью до краевых пикселей (расхождение — доли процента; большее означает ошибку СК или маски).
4. Сохраните таблицу `landuse_stats.csv`: класс, гектары, проценты.

**Ожидаемый результат:** таблица долей классов землепользования района, прошедшая контроль баланса площадей.

### Шаг 5: верификационный участок с ортофото (15 мин)

1. Добавьте учебный ортофотоплан в проект; выполните входной контроль по протоколу §1 лекции 4: СК, разрешение, пирамиды, визуальная сверка привязки с подложкой по 3–4 опознаваемым объектам.
2. Создайте в `landuse.gpkg` точечный слой `control_points` и расставьте **не менее 20 точек** в зоне покрытия ортофото (равномерно и по разным классам); в атрибутах — два поля: `truth` (класс по ортофото, ваше дешифрирование) и `mapped` (класс WorldCover в точке — считайте инструментом «Определить объекты»).
3. Постройте матрицу ошибок: сводная таблица `truth × mapped` (в электронной таблице или полевом калькуляторе). Посчитайте общую точность и найдите самую частую путаницу классов (§3 лекции 4).

**Ожидаемый результат:** слой контрольных точек + матрица ошибок + 2–3 предложения выводов («на участке карта надёжна для классов …, систематически путает … с …»).

### Шаг 6: компоновка карты (15 мин)

1. Проект → Создать компоновку. Разместите: карту классов с границей района, легенду, масштабную линейку, стрелку севера, заголовок («Землепользование <район>, <год данных WorldCover>»).
2. Добавьте врезку локализации (обзорная карта с положением района) и текстовый блок паспорта качества: источники с датами (WorldCover CC BY, OSM © участники OpenStreetMap ODbL, ортофото), число контрольных точек, общая точность, главная оговорка по классам.
3. Экспортируйте `landuse_map.pdf` и `landuse_map.png`.

**Ожидаемый результат:** самодостаточный картографический лист по чек-листу §4 лекции 4.

### Шаг 7 (по желанию): интерактивная версия и проверка кода

- Экспортируйте веб-карту плагином qgis2web, либо постройте интерактивную карту в Colab (`GeoDataFrame.explore()`); ноутбук-заготовка: `<URL будет назначен при создании репозитория ноутбуков>`.
- Если проходите [задание ИИ-ассистента](../ai-assistant.md) — используйте таблицу шага 4 как эталон для верификации скрипта агента.

## Продукт задания

По итогам практикума у вас должны быть:

- [ ] `landuse.gpkg` — граница района, контрольные точки (+ производные слои);
- [ ] `worldcover_raion.tif` — обрезанный слой классов в СК проекта;
- [ ] `landuse_stats.csv` — таблица классов (га, %) с пройденным контролем баланса;
- [ ] матрица ошибок по ≥20 контрольным точкам с выводами;
- [ ] `landuse_map.pdf`/`.png` — итоговая карта с паспортом качества.

**Самопроверка:** (1) сумма площадей классов = площадь района (± краевые пиксели); (2) каждый цвет карты есть в легенде и наоборот; (3) в паспорте качества указаны все источники с лицензиями и датами; (4) матрица ошибок построена по точкам, не участвовавшим ни в какой настройке.

!!! note "Применить к своему хозяйству — «Проект на ВАШЕЙ земле»"
    Замените район на территорию вашего хозяйства или сельского округа: граница — оцифровкой по подложке (лекция 1) или из ваших материалов; WorldCover покрывает любую территорию РК; контрольные точки — по вашему полевому знанию (вы знаете свою землю лучше любого ортофото). Продукт — та же карта с паспортом качества, но о ВАШЕЙ земле: основа для планирования угодий, разговора с акиматом или заявки. Дрон не обязателен: шаг 5 выполняется на полевом знании или на любом доступном детальном снимке.

## Дополнительные задания

1. Повторите шаги 3–4 для соседнего района и сравните структуру землепользования двух районов одной таблицей.
2. Скачайте сцену Sentinel-2, рассчитайте NDVI (§4.1 лекции 3) и добавьте на карту врезку «состояние растительности на дату» — с датой снимка в паспорте.
3. Постройте слой лесополос ИИ-сегментацией ортофото (§2.2 лекции 4) и оцените их суммарную протяжённость в зоне облёта.
