# ИИ-ассистент в работе: геопайплайн от агента и его верификация

> Модуль **[А2: Геоинформатика и пространственный анализ](../index.md)** · Уровень **Pro-code** (студент, инженер).
> Инструменты: **Claude Code / OpenCode** (терминальные кодинг-агенты; взаимозаменяемы — вендор-независимость платформы), QGIS — для независимой сверки. Обзорно: GIS Copilot, LLM-Find (агентные GeoAI-фреймворки).
> ⏱ **Трудозатраты:** ~45 мин. Рамка: [ИИ-инструменты в обучении](../../ai-tools.md).

!!! warning "Правило платформы: ИИ ускоряет — человек верифицирует"
    Результат агента без независимой проверки — не результат. Задание построено так, что верификация — не финальная формальность, а половина работы и главный оцениваемый навык. Всё задание выполнимо и без ИИ (обычным написанием скрипта) — ИИ-слой ускоряет, но не является условием прохождения.

## Цель

Пройти полный производственный цикл работы с кодинг-агентом на геозадаче: **постановка задачи → ревью сгенерированного кода → независимая верификация результата** — на задаче зональной статистики из [практикума](practicum/01-landuse-map-sko.md). Дополнительно (обзорно): испытать ассистента цепочек геообработки класса GIS Copilot и сравнить два способа работы.

**Предпосылки:** выполненный [практикум](practicum/01-landuse-map-sko.md) (его результаты — ваш эталон), материал лекций [2](lectures/02-qgis-python-stack.md) (чек-лист чтения геокода, §2.7) и [4](lectures/04-ai-uav-integration.md) (анатомия постановки задачи агенту, §2.3).

## Задание

### Шаг 1: эталон (уже есть)

Из практикума у вас есть ручной результат: `landuse_stats.csv` — площади и доли классов WorldCover по границе района, посчитанные инструментами QGIS и прошедшие контроль баланса площадей. Это ваш **независимый эталон**: он получен другим инструментом и другим путём, чем будет получен результат агента. Зафиксируйте его до начала работы с ИИ и не «подгоняйте» позже.

### Шаг 2: постановка задачи агенту (10 мин)

Откройте терминальный кодинг-агент (Claude Code или OpenCode) в папке с данными практикума. Сформулируйте задачу по анатомии из §2.3 лекции 4 — данные, операции, контроль, выход. Пример постановки (адаптируйте пути и СК под свой проект):

```text
Напиши Python-скрипт zonal_landuse.py (GeoPandas + rasterio/rasterstats):
1. Данные: граница района — слой boundary_raion из landuse.gpkg;
   растр классов — worldcover_raion.tif (категориальный, байт).
2. Операции: проверь и приведи СК обоих источников к EPSG:32642;
   валидируй геометрию границы; посчитай гистограмму классов растра
   внутри полигона (число пикселей каждого класса).
3. Контроль (обязательно напечатать): СК обоих слоёв после приведения;
   значение NoData растра; сумма площадей классов и площадь полигона
   границы — и их расхождение в процентах.
4. Выход: таблица agent_stats.csv: class_code, pixels, area_ha (пиксель
   10x10 м = 0.01 га), share_pct. Только открытые библиотеки.
```

Обратите внимание: требования «напечатать контрольные числа» — не украшение. Они превращают выполнение скрипта в протокол, который вы сможете проверить.

### Шаг 3: ревью кода ДО запуска (10 мин)

Не запускайте сгенерированный скрипт сразу. Пройдите по чек-листу §2.7 лекции 2 и письменно ответьте:

1. **СК:** есть ли явное приведение вектора и растра к одной метрической системе? Каким методом передискретизации, если растр перепроецируется (для категориального допустим только ближайший сосед — §3.3 лекции 1)?
2. **Валидность:** проверяется ли геометрия границы (`is_valid` / `make_valid`)?
3. **NoData:** учтён ли NoData растра при подсчёте гистограммы?
4. **Единицы:** верен ли пересчёт «пиксели → гектары» (и не зашит ли размер пикселя константой, противоречащей метаданным растра)?
5. **Контроль:** печатает ли скрипт затребованные контрольные числа?

Найденные проблемы верните агенту текстом («исправь: категориальный растр нельзя передискретизировать билинейно») и повторите ревью. Типовые ошибки агентов на этом классе задач — молчаливая работа в градусной СК, игнорирование NoData и константы, противоречащие данным, — все они ловятся этим чек-листом.

### Шаг 4: запуск и верификация результата (15 мин) — обязательный

1. Запустите скрипт; сохраните консольный вывод (контрольные числа) вместе с `agent_stats.csv`.
2. **Сверка с эталоном:** сравните `agent_stats.csv` с ручной таблицей `landuse_stats.csv` практикума класс за классом. Ожидание — совпадение долей классов с расхождением на уровне краевых эффектов (доли процента); заметное расхождение по любому классу — сигнал об ошибке (чаще — у одной из сторон в обработке NoData или краевых пикселей маски).
3. **Локализация расхождений:** если расхождение существенно — найдите причину (сравните число пикселей, NoData, способ обрезки по маске: «все затронутые пиксели» против «пиксели с центром внутри»). Задокументируйте, чей результат корректнее и почему; исправьте (свой шаг практикума или код агента) и добейтесь сходимости.
4. **Контроль инвариантов:** сумма долей = 100%; баланс площадей из консольного вывода в пределах долей процента; коды классов соответствуют легенде WorldCover.

### Шаг 5 (обзорно, по желанию): ассистент цепочек в QGIS (10 мин)

Если доступен ассистент класса GIS Copilot, дайте ему ту же постановку текстом и сравните построенную им цепочку геообработки со своей из практикума: какие шаги он выбрал, где потребовалось уточнение, что пришлось исправить. Краткий вывод (3–5 предложений) о сильных и слабых сторонах двух режимов работы (агент-кодер против ассистента-цепочки) добавьте к отчёту.

## Критерии зачёта

| # | Критерий | Свидетельство |
|---|---|---|
| 1 | Постановка задачи содержит данные, операции, контроль, выход | текст промпта в отчёте |
| 2 | Ревью кода до запуска: письменные ответы по 5 пунктам чек-листа, найденные проблемы возвращены агенту | заметки ревью + история правок |
| 3 | **Верификация:** сверка с независимым эталоном выполнена, расхождения локализованы и объяснены, сходимость достигнута | таблица сравнения эталон/агент + вывод |
| 4 | Контрольные числа скрипта сохранены и согласованы (баланс площадей, NoData, СК) | консольный вывод |
| 5 | Честность отчёта: указано, что исправлял агент, а что — вы; нерешённые вопросы названы | итоговый отчёт (0,5–1 стр.) |

Зачёт выставляется за **процесс** (ревью + верификация), а не за «красивую таблицу»: работа, в которой агентский результат принят без сверки с эталоном, не засчитывается, даже если числа верны.

!!! tip "Перенос навыка"
    Этот цикл — постановка, ревью, верификация — не про конкретный инструмент: тем же протоколом вы будете принимать код коллеги, скрипт со Stack Overflow и результат любого будущего агента. В [А3](../a3/index.md) он усложнится до поиска утечек данных в ML-пайплайне, в [А4](../a4/index.md) — до контроля пакетной фильтрации промеров по опорным глубинам.
