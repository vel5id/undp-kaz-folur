# ARCHITECTURE

Документ описывает **физическую архитектуру** кодовой базы платформы FOLUR: где что лежит, как части связаны и какие инварианты нужно держать в голове. Цель — чтобы новый разработчик за полчаса понял, *куда* вносить изменение, а не только *как*. Это карта страны, а не атлас: детали реализации — в комментариях рядом с кодом.

Формат вдохновлён [matklad, «ARCHITECTURE.md»](https://matklad.github.io/2021/02/06/ARCHITECTURE.md.html) и [rust-analyzer](https://github.com/rust-lang/rust-analyzer/blob/master/docs/dev/architecture.md).

## Обзор с высоты птичьего полёта

FOLUR — **учебная платформа**: 21 модуль (6 академических `a1`–`a6` + 15 профессиональных `p1`–`p15`) по цифровому агромониторингу для Северного Казахстана. Технически это **статический сайт без серверной части**: контент пишется в Markdown, собирается генератором MkDocs (тема Material) в готовый HTML, а вся интерактивность (тесты, сертификаты, прогресс) исполняется в браузере на ванильном JavaScript и хранится в `localStorage`. Публикуется на Firebase Hosting и GitHub Pages. Стоимость эксплуатации — ноль: нет ни сервера, ни базы данных, ни авторизации.

Поток на сборке: `docs/**.md` → `tools/validate_content.py` → `mkdocs build --strict` → `site/` → деплой.
Поток в браузере: MkDocs Material отдаёт страницу → клиентские IIFE подписываются на `document$` → навешивают тесты/навигацию/анимации на DOM.

## Codemap

### `docs/` — контент и клиент (публикуемая часть, `docs_dir` в `mkdocs.yml`)

- **`docs/modules/<code>/`** — 21 учебный модуль. У каждого фиксированный каркас: `index.md` (программа), `lectures/NN-*.md`, `practicum/*.md`, `ai-assistant.md`, `assessment/*.md`. Каркас — несущий инвариант (см. ниже).
- **`docs/javascripts/`** — весь клиентский код (грузится через `extra_javascript` в `mkdocs.yml`):
  - **`steppe.js`** (~645 стр.) — **слой интерфейса**. Функции: `readbar` (полоса прогресса), `lessonHead`, `bloomPills`, `stepsBar` (пошаговая навигация урока), `courseLanding` (лендинг модуля), `cardCovers` (генеративные SVG-обложки), `myLearning` (сводка прогресса), `pruneSidebarToModule`, `scrollReveal` (появление блоков при прокрутке), `enrichProse` (выноски, определения, списки и инлайн-код из сплошных абзацев Word-конвертации — меняется только разметка, не текст; обязана выполняться до `stepsBar`), `externalLinks` (внешние ссылки и редактор Python — в новой вкладке), `lessonGate` (последовательный доступ к шагам модуля). Точка входа — `init()`, вызывается на каждой смене страницы.
  - **`quiz-engine.js`** (~288 стр.) — **тест-движок**. `hash` (FNV-1a), `mulberry32` (PRNG), `buildVariant` (детерминированный вариант по ID слушателя), `render`, `makeCertWatcher`, `certCode`/`resultCode`. Здесь же константа `CERT_SALT`.
  - **`verify.js`** (~82 стр.) — страница проверки сертификата: `decode` сверяет контрольную сумму (тот же `CERT_SALT`).
  - **`qrcode.js`** (~2297 стр.) — **вендоренная** библиотека QR (Kazuhiko Arase, MIT, 2009). Не править; обновлять только целиком из первоисточника.
  - **`modules-manifest.js`** — **автогенерируется** `tools/gen_nav.py`. Экспортирует `window.FOLUR_MODULES` (код → {title, total}). Руками не трогать.
- **`docs/assets/css/`** — оформление «Степь»: `brand.css` (палитра), `restyle.css` (карточки, hero, scroll-reveal), `steppe-course.css` (лендинг модуля), `steppe-lessons.css`, `steppe-prose.css` (читаемость урока: меню, ссылки, код, выноски, замок шагов); плюс `docs/stylesheets/quiz-engine.css`.
- **`docs/files/`, `docs/datasets/`, `docs/pdf/`** — учебные CSV (уровень A), PDF-конспекты (генерируемые), скачиваемые артефакты.

### `tools/` — сборка и эксплуатация (не публикуется, запускается вручную/в CI)

- **`validate_content.py`** — валидатор контента (quiz-JSON, обязательные секции, плейсхолдеры). Гейт в CI: выход `1` = сборка не проходит.
- **`gen_nav.py`** — перегенерирует секцию `nav` в `mkdocs.yml` из `docs/modules/` и пишет `modules-manifest.js`. Заголовки — из первого H1 файла.
- **`gen_module_stubs.py`** — каркасы новых модулей.
- **`make_module_pdfs.mjs`** (Node + Playwright) + **`merge_pdfs.py`** — печать страниц сайта в 21 PDF-конспект.
- **`registry_check.py`** — батч-проверка кодов результатов для KPI-реестра (FNV-1a + `CERT_SALT` → CSV).
- **`anonymize_bathymetry.py`** — обезличивание батиметрии: реальные `Lat/Lon/Depth` → локальные `x_m,y_m,depth_m`; начало отсчёта уходит в **`SECRET-origin.json`** (не публикуется).
- **`deploy_firebase.sh`, `publish_platform.sh`** — деплой на Firebase и синхронизация репозитория.

### Конвейер обработки данных (закрытый контур, `data-not-anonymys/Main/`)

`Merge_points.py`, `Interpolation.py`, `Kriging.py`, `Analysis_Isobars_Full.py` — научная обработка батиметрии (сырьё → фильтрация → интерполяция поверхности → изобаты/объём). Порождает продукты уровня B; сырьё уровня C **никогда не попадает в git**.

### Конфигурация и CI

- **`mkdocs.yml`** — тема, `nav`, расширения (Mermaid, кастомный fence `quiz`), подключение JS/CSS. Единый источник структуры сайта.
- **`requirements.txt`** — `mkdocs-material>=9.5`.
- **`firebase.json` / `.firebaserc`** — хостинг и id проекта `folur-kaz-platform`.
- **`.github/workflows/deploy.yml`** (в **корне** репозитория) — единственный работающий CI: `validate → build --strict → Firebase deploy` (деплой при наличии секрета). ⚠️ Вложенный `project/platform/.github/workflows/deploy.yml` на GitHub **не запускается** (Actions читает только корневой каталог) — это дубликат.

## Архитектурные инварианты

Важнее всего то, чего в системе **нет** намеренно:

1. **Нет сервера, БД и авторизации.** Вся динамика — на клиенте. Не добавляйте серверных зависимостей, не заводите бэкенд без пересмотра всей модели.
2. **Нет сборки клиентского JS.** Файлы в `docs/javascripts/` отдаются как есть — поэтому это ES5-совместимый ванильный JS (`var`, IIFE, без `import`/JSX/TypeScript). Не вводите бандлер/транспайлер незаметно.
3. **Клиент не делает сетевых вызовов наружу.** Ни `fetch`, ни `XHR`, ни телеметрии. Данные слушателя (`localStorage`) не покидают браузер — это одновременно приватность и требование офлайна.
4. **Сырые данные уровня C не хранятся в git** (список исключений в `.gitignore`; `SECRET-origin.json` — офлайн). Публикуются только уровни A и B.
5. **`modules-manifest.js` — производный артефакт.** Его и `nav` в `mkdocs.yml` меняет только `gen_nav.py`.
6. **`CERT_SALT` синхронизирован в трёх местах:** `quiz-engine.js`, `verify.js`, `tools/registry_check.py`. Рассинхрон ломает проверку кодов.
7. **Каждый клиентский модуль идемпотентен** относительно мгновенной навигации Material (`document$` вызывает `init()` на каждой странице). Новый код обязан не дублировать эффекты при повторном заходе.
8. **Контент обязан проходить `validate_content.py` и `--strict`.** Модуль без обязательной секции просто не соберётся — это фича, а не баг.

## Границы

- **Сборка ↔ рантайм.** Python-инструменты и MkDocs работают на сборке; в браузере — только JS из `docs/javascripts/`. Эти миры не пересекаются: контент — единственный «протокол» между ними.
- **Автор контента ↔ разработчик.** Автор пишет доверенный Markdown (валидируется на сборке); разработчик трогает JS/CSS/tools. XSS-поверхности нет, потому что рантайм-ввод (ID слушателя) виден только самому слушателю.
- **Публикуемый контур ↔ закрытый контур данных.** `docs/` и данные A/B публичны; сырьё C и `SECRET-origin.json` — только внутри.

## Сквозные механизмы

- **Интеграция с Material instant-nav.** Каждый клиентский модуль стартует через `window.document$.subscribe(init)` с фолбэком на `DOMContentLoaded`. Это единая точка входа для всего UI.
- **Состояние в `localStorage`:** `folur-student-id`, `folur-results`, `folur-visited`, `folur-done` (шаги, пройденные до последнего раздела), `folur-gate-off` (модули, где слушатель снял замок). Единственный источник пользовательского состояния; сервера нет.
- **Последовательный доступ.** Следующий шаг модуля открывается, когда предыдущий пройден до последнего раздела (`lessonGate`). Замок мягкий: состояние живёт в браузере, поэтому на закрытой странице есть «Открыть без ограничений»; в режиме `__FOLUR_PDF__` и при печати замка нет.
- **Тесты не угадываются по длине ответа.** `validate_content.py` отклоняет вопрос, где верный вариант длиннее самого длинного дистрактора более чем на 15 %, и банк, где верный вариант оказывается самым длинным чаще чем в 40 % вопросов.
- **Детерминизм.** `hash` (FNV-1a) + `mulberry32`/`seedRand` дают воспроизводимые по seed результаты: индивидуальные варианты тестов (`buildVariant`) и обложки карточек (`coverSvg`) одинаковы у одного слушателя и воспроизводимы преподавателем.
- **Целостность сертификатов.** `certCode` = base64(payload + FNV-1a(payload+`CERT_SALT`)). Это **контрольная сумма, не подпись** (соль публична). Источник истины по KPI — реестр; коды его лишь сопровождают. Полное решение — Open Badges (Этап 4).
- **Доступность и печать.** Анимации и надстройки обязаны уважать `prefers-reduced-motion` и флаг `window.__FOLUR_PDF__` (режим генерации PDF-конспектов через Playwright — контент печатается сплошным).
- **Обезличивание данных.** Политика A/B/C реализована в `anonymize_bathymetry.py`; риск деанонимизации по форме берега снят синтетическими фигурами в уроках.
- **i18n-готовность.** Структура допускает казахскую локализацию без перестройки (тема Material с `language`, контент по каталогам).

## Куда вносить типовые изменения

| Задача | Где |
|---|---|
| Добавить/править урок | `docs/modules/<code>/…`, затем `gen_nav.py` |
| Новый модуль | `gen_module_stubs.py` → контент → `gen_nav.py` |
| Логика тестов/сертификатов | `docs/javascripts/quiz-engine.js` (+ `verify.js`, `registry_check.py` при смене соли/формата) |
| Внешний вид, анимации | `docs/assets/css/*` (+ `steppe.js` для поведения) |
| Навигация/меню/лендинги | `steppe.js` (`stepsBar`, `courseLanding`, `pruneSidebarToModule`) |
| Правила валидации | `tools/validate_content.py` |
| Хостинг/деплой/CI | `.github/workflows/deploy.yml`, `firebase.json`, `tools/deploy_firebase.sh` |
| Обработка/публикация датасета | `data-not-anonymys/Main/*`, `tools/anonymize_bathymetry.py` |
