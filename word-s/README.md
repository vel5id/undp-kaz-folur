## Чего я (агент) об этих файлах НЕ знаю — и не выдумываю

Честный перечень пробелов, которые **не подтверждены** из самих файлов или из `_shared/`:

- **Версия/финальность.** Суффикс `_ok` у тендерной заявки *похоже* означает финальную/
  согласованную версию, но это **не подтверждено**. Номера ревизий, статус «черновик vs
  поданная финальная» внутри документов мной не верифицированы.
- **Авторство и даты создания.** Кто и когда готовил документы — неизвестно. Mtime файлов
  (20.06.2026) — это время копирования в WSL, **не** дата авторства.
- **Полное содержимое заявки (1.9 МБ).** Прочитан только верхнеуровневый перечень форм
  (A–G). Тело форм, вложенные изображения/сканы, приложения **построчно не вычитаны**.
  Размер 1.9 МБ указывает на встроенные изображения/сканы — их содержание не описано.
- **Каноничность docx vs `.work/source/*.txt`.** Если извлечённый текст и оригинал
  разойдутся — авторитетен `.docx`; идентичность извлечения мной не сверялась побайтно.
- **Происхождение `:Zone.Identifier`.** Это Windows alternate-data-stream «mark of the web»
  (файлы скачаны/перенесены через Windows). Источник скачивания неизвестен; это служебный
  мусор, не часть содержимого (см. ниже).
- **Юридический/контрактный статус.** Вне зоны проекта (CLAUDE.md: бюджет/контракт/право
  не ведём). Актуальность заявки на текущую дату не подтверждается.

## Открытое решение: git или gitignore для самих `.docx`

На момент этой заметки `.docx` **не отслеживаются git** (untracked). Это authoritative-входы,
и для провенанса их разумно хранить в version control, **но** это бинарники (заявка — 1.9 МБ),
что раздувает историю и трудно полностью откатывается. Решение оставлено за владельцем репо.
Файлы `:Zone.Identifier` — служебный мусор Windows, добавлены в `.gitignore` (не коммитятся).
